# Pre-registration: LLM induces expert-selection rules at cold start in new scenarios (switch-llm-coldstart-v3, 2026-10-01, fixed before any readings on new scenarios)

## Facts obtained from development that determine this version's design

- Gate: block-by-block selection without reasoning (DeepSeek flash, non-reasoning mode) reaches only 0.639 on the probe and does not pass; in reasoning mode the model writes rule functions from the same 16 examples that agree with the predefined rules at 0.994 (switch-llm-rule-induction-probe-v1 holds).
- Development set (870 calls, extracted from the four v2 scenarios whose results had already been seen, switch-llm-rule-induction-dev-v1): with all blocks as evidence, the reasoning does not finish; compressed to per-call summaries plus 8 block examples per call, it can produce rules, but when the rules only return a fixed expert, low bandwidth collapses on outlier calls not present in the first 5 calls. Version 3 allows rules to compute the expert dynamically from the current block's statistics, but still returns a fixed expert. Version 4 adds old deployment experience (per-expert summaries for each old scenario, the 6 blocks with the largest per-expert error, the same information as the lightweight models' training data, so the inputs are aligned), achieving a development-set average of 0.900, the best of all methods (MINPSEUDO 0.929, zero-shot 0.917, NN0 0.943); per scenario: high bandwidth 0.280, low bandwidth 1.620, high volatility 0.988, low volatility 0.712, three wins and one loss against MINPSEUDO, still losing on low bandwidth. Development is frozen at version 4; no further tuning on the development set.
- All 870-call LLM results have been seen and are used only for development; this version is tested only on never-before-seen new scenarios.

## New scenarios and draws

- Five new scenarios (coldstart-newscen-data-v1): medium bandwidth (71 calls at a constant 2 to 6 Mbps in evaluate_dataset, never used before); testbed-collected 4G driving, 4G walking, 3G tram, 3G subway (36 real trace windows each, selected by the coldstart_real_v1 rules, all valid runs counted).
- Block table uses the same code as the 870 calls (newscen_table_v1.py, element-wise identical on the 870-call reconstruction; the expert-export equivalence check is recorded in the registry).
- 3 draws per scenario, seed 20261101 + 100 × scenario index + draw number. Grouped by trace: after shuffling traces, windows are taken in order, and the first 5 calls form the accumulated data; remaining windows in the traces of the first 5 calls do not enter evaluation; evaluation calls are all the rest. Medium bandwidth has each call as its own group.

## Method and controls

- **LLM rule induction (main arm)**: one call per scenario draw to deepseek-flash in reasoning mode (temperature 0, output limit 64k), prompt generated by coldstart_rule_v1.prompt_v4, identical to development version 4 (12 groups checked identical): task description, 25 feature definitions, old deployment experience (all four scenarios of the 870 calls, i.e., the training data of NN0 and GBDT0), per-call summaries and 8 block examples per call for the first 5 calls of the new deployment, requirements for writing rules (may return a fixed expert or compute the expert from the current block's statistics, at most 4 conditions). Rules execute block by block in a restricted namespace; blocks where no answer is produced or an error occurs use the default expert and the block count is reported; if no usable rule exists for the whole group, the default expert is counted.
- **Controls (all deployable)**: default expert; MINPSEUDO; MAJ5; NN0, GBDT0 (trained on all blocks of the 870 calls); NN5, GBDT5 (870 calls plus the first 5 calls); DT5 (decision tree trained only on the blocks of the first 5 calls, depth at most 3, given exactly the same examples as the LLM, a classical induction algorithm on the same evidence); ARB (picks from default, MINPSEUDO, MAJ5, NN0, GBDT0 the one with the lowest average per-call error on the first 5 calls). Training recipe identical to switch_llm_zeroshot_baselines_v1 (selection checked element-wise identical).

## Criteria

Metric: per-call error on evaluation calls divided by that scenario's default-expert reference value, averaged over the 3 draws per scenario first, then equally weighted across the five scenarios.

- Strongest single control b*: the control above with the lowest five-scenario average, selected post hoc from this version's evaluation results, most unfavorable to us.
- Significantly better on a single scenario: LLM minus b* less than 0 for that scenario, and the upper bound of the 95% interval from 2000 resamples of evaluation calls within each draw is less than 0.
- **Holds**: at least three of the five scenarios significantly better, and the five-scenario average difference no greater than −0.03 with interval upper bound less than 0.
- **Does not hold**: five-scenario average difference no less than +0.03 with interval lower bound greater than 0; or at least two scenarios significantly worse.
- **Inconclusive**: everything else.
- Scoring script switch_llm_coldstart_v3_run_score.py passes self-check on four cases (holds, inconclusive, does not hold, tie).

## Report only

Per-scenario readings for each control; the post hoc best control per scenario; median per-call error; the induced rules in full; bad block count; crossover curves (NN, GBDT trained on the 870 calls plus the first 10, 20 calls, compared with the LLM rules on calls outside the traces of the first 20 calls).

## Predictions unfavorable to us

- The induced rules may degenerate into copying one of the majority or minimum-deviation rules, losing to another rule in other scenarios.
- The testbed observations differ in distribution from the simulated data, so all methods' readings will shift, and b* may be a lightweight model trained on the 870 calls.
- If outlier calls in a new scenario are not in the first 5 calls, any method relying on the first 5 calls will suffer.
- With 3 draws per scenario and twenty to thirty evaluation calls, single-scenario intervals may be too wide to detect significance.
